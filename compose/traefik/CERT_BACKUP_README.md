# Traefik Certificate Backup & Restoration System

**Purpose**: Automatically backup and restore SSL/TLS certificates managed by Traefik's ACME configuration.

## Quick Start

```bash
# Backup current certificates
./cert-backup.sh backup

# List all backups
./cert-backup.sh list

# Restore from a backup
./cert-backup.sh restore /root/site/websites/compose/traefik/cert-backups/20260602_121530_certs

# View status
./cert-backup.sh status

# Cleanup old backups (keep last 10)
./cert-backup.sh cleanup 10
```

## Directory Structure

```
/root/site/websites/compose/traefik/
├── acme/                          # Traefik ACME directory (active certificates)
│   └── acme.json                  # Certificate store (generated by Traefik)
├── cert-backups/                  # Backup directory
│   ├── 20260602_120530_certs/     # Backup 1 (YYYYMMDD_HHMMSS format)
│   │   ├── acme.json              # Backed up certificate file
│   │   └── backup-metadata.txt    # Backup info & timestamp
│   ├── 20260602_130045_certs/     # Backup 2
│   │   ├── acme.json
│   │   └── backup-metadata.txt
│   └── pre-restore_1717XXX_certs/ # Safety backups (before restore operations)
├── cert-backup.sh                 # This backup script
├── traefik.yml                    # Traefik configuration
├── dynamic/                       # Dynamic routing config
└── Dockerfile                     # Traefik Docker image
```

## Backup Operations

### Manual Backup
```bash
cd /root/site/websites/compose/traefik
./cert-backup.sh backup
```

**Output**:
- Creates dated directory: `cert-backups/YYYYMMDD_HHMMSS_certs/`
- Copies `acme.json` with all certificates
- Generates `backup-metadata.txt` with:
  - Backup timestamp
  - File list and sizes
  - Certificate domain information (if jq available)
  - Expiry dates

**Example Backup Directory**:
```
cert-backups/20260602_145230_certs/
├── acme.json                    (12.4 KB)
└── backup-metadata.txt          (1.8 KB)

Content of backup-metadata.txt:
  Traefik Certificate Backup
  ==========================
  Backup Date: 2026-06-02 14:52:30
  Timestamp: 20260602_145230
  Source Directory: /root/site/websites/compose/traefik/acme
  Backup Directory: /root/site/websites/compose/traefik/cert-backups/20260602_145230_certs
  
  Files Backed Up:
  -rw------- 1 root root 12.4K Jun  2 14:52 acme.json
  -rw-r--r-- 1 root root 1.8K Jun  2 14:52 backup-metadata.txt
  
  Certificate Information:
  Domain: ctc-research.com, Expiry: 2026-09-02T10:23:45Z
  Domain: structa.cloud, Expiry: 2026-09-02T10:24:15Z
  Domain: vresume.structa.cloud, Expiry: 2026-09-02T10:25:00Z
```

### Automatic Backup (Cron Job)

**Setup Daily Backup at 2 AM**:
```bash
# Edit crontab
crontab -e

# Add this line (runs daily at 2:00 AM)
0 2 * * * cd /root/site/websites/compose/traefik && ./cert-backup.sh backup >> /var/log/traefik-backup.log 2>&1

# Or for every 6 hours
0 */6 * * * cd /root/site/websites/compose/traefik && ./cert-backup.sh backup >> /var/log/traefik-backup.log 2>&1
```

**Verify Cron Job**:
```bash
# View installed cron jobs
crontab -l

# Check backup log
tail -f /var/log/traefik-backup.log

# Manually trigger backup (test)
cd /root/site/websites/compose/traefik && ./cert-backup.sh backup
```

## Restoration Operations

### Restore from Backup
```bash
# 1. List available backups
./cert-backup.sh list

# 2. Choose a backup and restore it
./cert-backup.sh restore /root/site/websites/compose/traefik/cert-backups/20260602_145230_certs

# 3. Restart Traefik to apply new certificates
docker compose restart traefik

# 4. Verify certificates loaded
docker compose logs traefik --tail 50
```

### Restoration Process
1. **Safety Backup**: Before restoring, current certificates are backed up to `pre-restore_<timestamp>_certs/`
2. **File Restore**: Backup's `acme.json` copied to `/root/site/websites/compose/traefik/acme/`
3. **Permissions**: File permissions set to `600` (read/write for owner only)
4. **Service Restart**: Traefik must be restarted to reload certificates

### Restore from Emergency Pre-Restore Backup
```bash
# If something went wrong after restore, use the pre-restore backup
./cert-backup.sh restore /root/site/websites/compose/traefik/cert-backups/pre-restore_1717XXX_certs

# Restart Traefik
docker compose restart traefik
```

## Disaster Recovery Scenarios

### Scenario 1: Lost All Certificates
**Problem**: The `acme.json` file got corrupted or deleted, certificates no longer work.

**Solution**:
```bash
# 1. Restore from latest backup
./cert-backup.sh list
./cert-backup.sh restore /root/site/websites/compose/traefik/cert-backups/20260602_145230_certs

# 2. Restart Traefik
docker compose restart traefik

# 3. Verify certificates are loaded
docker compose logs traefik --tail 50 | grep -i "certificate\|error"
```

### Scenario 2: Bad Restore - Need to Rollback
**Problem**: Restored wrong backup and websites are down.

**Solution**:
```bash
# 1. Safety backup from failed restore is automatically created
ls -la /root/site/websites/compose/traefik/cert-backups/pre-restore_*

# 2. Restore from the pre-restore backup
./cert-backup.sh restore /root/site/websites/compose/traefik/cert-backups/pre-restore_1717XXX_certs

# 3. Restart Traefik
docker compose restart traefik
```

### Scenario 3: Expired Certificates
**Problem**: All certificates have expired, Let's Encrypt rejected renewal.

**Solution**:
```bash
# 1. Save current (expired) certs for reference
./cert-backup.sh backup

# 2. Delete the corrupted acme.json to force renewal
rm /root/site/websites/compose/traefik/acme/acme.json

# 3. Restart Traefik (it will request new certs)
docker compose restart traefik

# 4. Monitor renewal process
docker compose logs traefik -f --tail 50

# 5. Once successful, backup new certificates
./cert-backup.sh backup
```

### Scenario 4: Certificate Storage Full
**Problem**: Too many backups taking up disk space.

**Solution**:
```bash
# 1. Check current usage
./cert-backup.sh status

# 2. Remove old backups, keep only recent ones
./cert-backup.sh cleanup 5

# 3. Verify cleanup
./cert-backup.sh list
```

## Integration with Docker

### Backup During Container Deployment
Add to `docker-compose.yml` post-deployment:
```yaml
# After 'docker compose up -d' completes
post_deployment:
  - command: 'cd /root/site/websites/compose/traefik && ./cert-backup.sh backup'
    description: 'Backup new certificates after successful deployment'
```

### Backup on Container Restart
The Traefik container in the docker-compose.yml should have restart policy:
```yaml
traefik:
  restart: unless-stopped
  # After restart completes and certs are loaded:
  # - Certificates are automatically reloaded
  # - Run backup: ./cert-backup.sh backup
```

## Monitoring & Alerts

### Check Backup Age
```bash
# List backups sorted by date
ls -ltr /root/site/websites/compose/traefik/cert-backups/*/backup-metadata.txt

# Find backups older than 7 days
find /root/site/websites/compose/traefik/cert-backups -type d -mtime +7 -name "*_certs"
```

### Alert if No Recent Backup
```bash
#!/bin/bash
# Check if latest backup is older than 24 hours
LATEST_BACKUP=$(ls -t /root/site/websites/compose/traefik/cert-backups/*/backup-metadata.txt | head -1)
LATEST_TIME=$(stat -c %Y "$LATEST_BACKUP")
NOW=$(date +%s)
DIFF=$((NOW - LATEST_TIME))
THRESHOLD=$((24 * 60 * 60))  # 24 hours

if [ $DIFF -gt $THRESHOLD ]; then
  echo "WARNING: Certificate backup is older than 24 hours!"
  # Send alert, create ticket, etc.
fi
```

## Troubleshooting

### Backup Failed: "No acme.json found"
**Cause**: Traefik hasn't generated certificates yet.
**Fix**: 
```bash
# Wait for Traefik to generate certificates
docker compose logs traefik -f | grep -i "certificate\|acme"

# Once certificates are generated, retry backup
./cert-backup.sh backup
```

### Restore Failed: "Permission denied"
**Cause**: Need write permissions to acme directory.
**Fix**:
```bash
# Check permissions
ls -la /root/site/websites/compose/traefik/acme/

# If needed, fix permissions
chmod 700 /root/site/websites/compose/traefik/acme/
chmod 600 /root/site/websites/compose/traefik/acme/acme.json
```

### Traefik Not Loading Restored Certs
**Cause**: Traefik needs restart to reload certificates.
**Fix**:
```bash
# Restart Traefik
docker compose restart traefik

# Wait for startup and verify
sleep 10
docker compose logs traefik --tail 30 | grep -i "certificate\|loaded"

# Test HTTPS access
curl -I https://ctc-research.com/
curl -I https://structa.cloud/
curl -I https://vresume.structa.cloud/
```

### jq Not Available (Certificate Info Missing)
**Cause**: `jq` JSON processor not installed in container/host.
**Fix**:
```bash
# Install jq (on Linux)
sudo apt-get update && sudo apt-get install -y jq

# Or in Docker container
docker exec traefik apt-get update && docker exec traefik apt-get install -y jq

# Retry backup to get certificate info
./cert-backup.sh backup
```

## Best Practices

1. **Regular Backups**: Setup daily automated backups via cron
2. **Keep History**: Maintain last 10-20 backups for safety
3. **Test Restoration**: Periodically test restore process in staging
4. **Monitor Expiry**: Check certificate expiry dates before they expire
5. **Document Changes**: Note what was in each backup (already done in metadata)
6. **Cleanup Regularly**: Remove old backups to save disk space
7. **Verify After Restore**: Always test HTTPS connectivity after restore
