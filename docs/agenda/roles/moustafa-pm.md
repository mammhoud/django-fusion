# Moustafa — Product Manager + Marketing

> **Goal:** Decide what gets built and in what order, and be the first person to
> check that it is actually done.
> **Validated by:** Mahmoud (scope, claims) · **Review:** weekly

## Tasks

| # | Task | Done when | Validated by |
|---|---|---|---|
| 1 | Sprint planning + backlog grooming | The sprint has one goal and sized tasks | Mahmoud |
| 2 | Write acceptance criteria before work starts | Every task has a "done when" a validator can check | Mahmoud |
| 3 | Validation pass with the team | Each finished task is marked validated or sent back | Mahmoud |
| 4 | Campaign readout | Reached, converted, and lesson — in one table | Asmaa |
| 5 | Public claim wording | Each claim matches its evidence level | Mahmoud |
| 6 | Lead follow-up with the commercial owner | Every open lead has a next action and a date | Mahmoud |

## Works with

| Person | On |
|---|---|
| Mahmoud — General Manager | Scope approval, pricing, claims sign-off |
| Yahia — Front-end + UX | Specs → design drafts → acceptance |
| Asmaa — Data | Metric definitions, campaign readouts |
| Dariia — Contributor | Content drafts and channel copy |

## Blocked?

If a task cannot be accepted, write the missing acceptance line and return it —
do not accept "mostly done". Rejected tasks go back to the board with a reason.
