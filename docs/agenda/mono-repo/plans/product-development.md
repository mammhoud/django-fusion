# Product Development Lifecycle

> **Description:** Evidence-led lifecycle from customer problem and product description through development, release, marketing, sales, adoption, and learning.

## Lifecycle

- **Market research** → Product description → Discovery → Roadmap
- **Roadmap** → Design → Build → Test → Pilot → Release
- **Release** → Campaign → Sale → Adoption → Feedback → Iteration

## Stage contracts

| Stage | Output | Linked objects |
|---|---|---|
| Research | Evidence, assumptions, validation questions | Market Research, Goal |
| Product definition | Audience, promise, edition, pricing hypothesis | Product, Edition |
| Discovery | User stories and acceptance outcomes | Feature, Plan |
| Planning | Milestones, owners, dependencies, risks | Project, Plan, Team |
| Build | Implemented capability and migration | Feature, Component, Task |
| Validate | Tests, pilot, accessibility, support readiness | Release, Guide, Claim |
| Launch | Product page, campaign, demo/trial, sales handoff | Campaign, Sales, Commerce |
| Learn | Customer feedback, metrics, corrective decisions | Research, Goal, Decision |

## Formint vertical slice

Branch → order → KDS → sync → report is the first Professional proof path. Preserve combos, modifiers, extras, notes, offline behavior, Arabic/RTL, and responsive states before retiring legacy implementations.

## Decision gates

No feature moves to marketing as available until implementation and acceptance evidence exists. No roadmap item is prioritized only by opinion; connect it to research, customer impact, risk, and team capacity.
