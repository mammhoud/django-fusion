## Part 3: Redis-Free Login

| Task | Files | Status |
|------|-------|--------|
| **RESP PING probe** | `backend/configs/default/__init__.py` — `_redis_reachable()` now performs an actual RESP `PING` exchange (honoring `REDIS_URL`) instead of a bare TCP connect | ✅ |
| **`_use_redis` decision** | Same file — DEBUG validates Redis via probe; production always requires the configured Redis | ✅ |
| **Cache/channel fallbacks** | LocMemCache + `InMemoryChannelLayer` when Redis is missing or a non-Redis listener squats the port | ✅ |

### Why This Mattered

The Kiro app held port 6379 and answered TCP without speaking Redis, so the old
socket probe reported "reachable", settings configured `RedisCache`, and
allauth's login 500'd at the protocol handshake. The RESP PING probe now
distinguishes a real Redis from a squatting listener.

**Verified:** `POST /accounts/login/` → 302 with a session cookie; authenticated
screens render 200 with fusion content; no minted session needed for the browser demo.
