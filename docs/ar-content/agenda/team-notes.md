# 📝 ملاحظات الفريق — ملاحظات اجتماعات، قرارات وعقبات

> **الغرض:** ذكاء الفريق المكتوب — ملاحظات الاجتماعات، القرارات الرئيسية، العقبات، والأحداثworth ذكر. قابلة للبحث، مُسجَّلة بالتاريخ، ومرتبطة بالميزات والمهام.

## 📋 شكل مدخلة الملاحظة

كل مدخلة يجب أن تكون مُسجَّلة بتاريخ وتصنَّف:

```markdown
### YYYY-MM-DD — [نوع اجتماع/حدث] — [عنوان موجز]

**الحضور:** @عضو1، @عضو2، @عضو3

**الموضوع/الجدول:** [عن الخارج الاجتماع/الحدث]

**نقاط رئيسية:**
- نقطة 1
- نقطة 2

**القرارات المتخذة:**
- قرار 1 — [السبب إن كان notable]
- قرار 2

**عناصر العمل:**
- [ ] @المسؤول — وصف المهمة — الموعد YYYY-MM-DD
- [ ] @المسؤول — وصف المهمة — الموعد YYYY-MM-DD

**العقبات/المخاطر:**
- وصف العائق — المالك: @فرد

**الروابط:**
- ميزة ذات صلة: [`feature-tracking.md`](../feature-tracking.md) § اسم الميزة
- مهمة ذات صلة: [`task-tracking.md`](../task-tracking.md) § عنوان المهمة
- خطة ذات صلة: [`plans/path.md`](../plans/path.md)
- جدول الاجتماع: [`meeting-agenda.md`](../meeting-agenda.md)
```

## ✍️ إضافة ملاحظات جديدة

عندما يكون لديك اجتماع أو تتخذ قرارًا مهمًا:

1. **انسخ شكل المدخلة** أعلاه
2. **أَثْنِ التاريخ** بتاريخ الاجتماع
3. **صنّف** — نوع الاجتماع (تخطيط سبرينت، اجتماع يومي، مراجعة، retrospective، قرار، حادثة)
4. **اربط خارجيًا** — رجّع الميزة أو المهمة أو الخطة ذات الصلة
5. **سجّل عناصر العمل** مع المسؤولين والمواعيد النهائية
6. **سجّل العقبات** مع المالكين

## 🔄 الصيانة

- **أضف ملاحظات بعد:** كل اجتماع، كل قرار مهم، كل حادثة
- **حدّث الملاحظات عندما:** عناصر العمل تُكمل، العقبات تُحل، القرارات تتغير
- **رَجِّع في PRs:** ربط بالملاحظة ذات الصلة عندما PR ينفذ قرارًا
- **أرشيف ملاحظات قديمة:** عندما يُغَلَّق مشروع، انقل الملاحظات لقسم أرشيف أو ملف

## ملاحظات وإرشادات

- ملاحظات الفريق ليست بديلًا للخطط التفصيلية — هي سجل القرارات
- إذا قرار يؤثر ملفات multiple، اكتبها هنا AND حدّث خطة
- عناصر العمل بدون مالكين ومواعيد نهائية هي مجرد أمنيات — assignها دائمًا
- قالب الملاحظة خفيف نيابة عنه — لا تبالغ في هندسته
