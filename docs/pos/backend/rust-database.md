├── mod.rs          # 🔴 Connection, migrations, path resolution

└── models.rs       # 🔴 Rust structs (Queryable, Insertable, AsChangeset)

projects/pos/src-tauri/migrations/

> ⚠️ **Warning:** `schema.rs` is auto-generated by `diesel print-schema`. Never edit it directly — edit migrations and regenerate.

## Connection Management (`mod.rs`)

### Database Path Resolution

```
DATABASE_URL env var set?
  ├── Yes → Use it (relative/absolute path)
  └── No  → Platform app data directory + "restaurant.db"
```

> 💡 **Tip:** For development, set `DATABASE_URL=restaurant.db` in `projects/pos/.env` to use the project root.

### Key Functions (🔴 Not Customizable)

```rust
// Resolve DB path (env var or app data dir)
pub fn get_db_path(app: &AppHandle) -> Result<PathBuf, String>

// Fallback for standalone binaries (seed, etc.)
pub fn get_db_path_from_env() -> Result<PathBuf, String>

// Open a connection
pub fn open_conn(db_path: &PathBuf) -> Result<SqliteConnection, String>

// Run pending migrations (called at app startup)
pub fn run_migrations(db_path: &PathBuf) -> Result<(), String>
```

### Auto-Migration

Migrations run automatically on every app launch via `run_migrations()`. No manual migration step needed.

```rust
pub const MIGRATIONS: EmbeddedMigrations = embed_migrations!("migrations");
```

## Model Patterns

### Queryable (Read)

```rust
#[derive(Debug, Queryable, Selectable, Serialize, Deserialize, Clone)]
#[diesel(table_name = crate::db::schema::products)]
pub struct Product {
    pub id: i32,
    pub name: String,
    pub price: f64,
    pub unit: String,
    pub category_id: Option<i32>,
    pub image: Option<String>,
    pub created_at: NaiveDateTime,
    pub updated_at: NaiveDateTime,
    pub uploaded: bool,
}
```

### Insertable (Create)

```rust
#[derive(Debug, Insertable, Deserialize)]
#[diesel(table_name = crate::db::schema::products)]
pub struct NewProduct {
    pub name: String,
    pub price: f64,
    pub unit: String,
    pub category_id: Option<i32>,
    pub image: Option<String>,
}
```

> 💡 **Tip:** `New*` structs omit auto-generated fields (id, timestamps). Diesel fills these from the database defaults.

### AsChangeset (Update)

```rust
#[derive(Debug, AsChangeset, Deserialize)]
#[diesel(table_name = crate::db::schema::products)]
pub struct UpdateProduct {
    pub name: Option<String>,
    pub price: Option<f64>,
    pub unit: Option<String>,
    pub category_id: Option<i32>,
    pub image: Option<String>,
}
```

> 💡 **Tip:** `Update*` structs use `Option<T>` — only `Some` values are updated. `None` fields are skipped.

## Migration System

### Migration Files

```
migrations/
├── 2026-01-01-000000_create_initial/       # Core tables
│   ├── up.sql   — CREATE TABLE statements
│   └── down.sql — DROP TABLE IF EXISTS
├── 2026-01-02-000000_create_users/         # Auth tables
├── 2026-07-15-000000_add_product_image/     # Product images
├── 2026-07-16-000000_add_enterprise_features/  # Enterprise tables
└── 2026-07-17-000000_gaming_center_seed/   # Gaming preset data
```

### Adding a Migration (🟡 Delegate)

```bash
cd POS/src-tauri
diesel migration generate add_new_table

# Edit migrations/<timestamp>_add_new_table/up.sql
# Edit migrations/<timestamp>_add_new_table/down.sql

# Regenerate schema.rs
diesel print-schema > src/db/schema.rs
```

> ⚠️ **Warning:** Always provide both `up.sql` and `down.sql`. The seed binary uses `down.sql` for stripping presets.

## Customization Guide

### 🟢 Customizable
| What | How |
|------|-----|
| Add a table | Create migration → `diesel print-schema` → add models |
| Add columns | Create migration → regenerate schema → update models |
| Seed data | Edit migration `up.sql` files or create new preset migration |

### 🔴 Not Customizable
| What | Why not |
|------|---------|
| `mod.rs` functions | Connection management, path resolution — change breaks all ops |
| `schema.rs` | Auto-generated from migrations |
| Migration auto-run | Every app launch runs `run_migrations()` — don't bypass |
| Existing table schemas | Migrations are additive — edit existing tables via new migrations |

### 🟡 Delegate Pattern
| Pattern | How |
|---------|-----|
| Add table | diesel migration → `print-schema` → add model structs → add ops module |
| Add seed preset | Create migration with `up.sql`/`down.sql` → add to `seed_with_preset()` |
| Query new table | Use `open_conn()` → Diesel query in operations module |
