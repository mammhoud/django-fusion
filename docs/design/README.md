# 🎨 Design & Frontend — Documentation Suite

> 🧩 **Purpose:** Complete project documentation for the shared theme engine,
> SCSS architecture, component system, design system, django-fusion
> integration, and dynamic template fields — delivered as four guides.

## The Four Guides

| Guide | Audience | What it answers |
|---|---|---|
| [🏛️ Architecture Guide](architecture-guide.md) | Architects, senior engineers | How the systems fit together, token flow, request lifecycle, diagrams |
| [🧑‍💻 Developer Guide](developer-guide.md) | Engineers implementing features | Hands-on recipes: create a theme, build a component, wire the engine, render templates |
| [🧑‍🎨 User Guide](user-guide.md) | Editors, operators, product owners | Activate themes, switch dark mode, author `{{ variable }}` templates, preview content |
| [🔄 Migration Guide](migration-guide.md) | Engineers upgrading existing code | Move off `.archives/theme`, convert CSS→SCSS, adopt `--fu-*` tokens, migrate templates |

## Remarks & Notes

- The shared theme library at `projects/assets/theme/` is the **canonical**
  source for the `--fu-*` token system. The legacy page
  `docs/dev/customization/design-system.md` documents the older hex
  `--color-*` conventions and is superseded by `DESIGN-SYSTEM.md` for new
  work; see the [Migration Guide](migration-guide.md) for the token swap.
- `docs/content/` is generated by `scripts/prepare-content.mjs` — never edit
  it; author only the Markdown in this directory.
- Every generated guide ends with a `## Remarks & Notes` section; AI-written
  sections carry the `<!-- AI-generated: review needed -->` marker.
