Precis Main / Operations

Fusion render flow, without the guesswork.

The unified Precis product serves one content source through Django and django-fusion, HTMX fragments, or Astro data APIs. This page is the command and contract reference for local work, production rollout, and Nx automation.

Canonical path
projects/structa.cloud/ (renamed from precis/precis-main)

Compatibility aliases
precis-lms · precis-landing
The contract

One content source, three response shapes.

Browser

Traefik or the local Astro dev server receives a page, fragment, or API request.

Route

Django URLs select Wagtail, a PageHandler, a fragment endpoint, or a data endpoint.

Render

Fusion resolves the effective render preference from settings and request headers.

Response

Full HTML serves SEO pages, HTMX returns a fragment, and JSON feeds Astro islands.

Assets

Tailwind and webpack source assets are built once and consumed by both roads.

Commands

Choose the environment explicitly.

Local Compose

Loads the local overlay, publishes Django on 8074 and Astro on 3000, and keeps debug behavior local.

cd projects/structa.cloud
make validate-local
make deploy-local

Production Compose

Uses the base stack only and reads the root deployment environment. It preserves named volumes.

cd projects/structa.cloud
make validate-production
make deploy-production

Project quality gates

Run the narrow checks from the project boundary before a rollout.

make config-check
make check
make backend-test
make build-prod

Dispatcher aliases

Use the repository dispatcher when working from projects/.

cd projects
make show-config WEBSITE=structa.cloud
make check WEBSITE=structa.cloud
make test WEBSITE=structa.cloud
make docker-up WEBSITE=structa.cloud
Nx bridge

Make remains the source of truth; Nx supplies the graph.

The precis-main-assets project exposes cache-aware targets that delegate to the project Makefile. This prevents Nx and direct project commands from drifting.

Nx targetDelegates toUse
checkmake checkAstro diagnostics, config validation, and backend checks.
testmake backend-testBackend test boundary for the unified product.
buildmake buildAssets, CSS, skeleton manifest, and Astro production build.
deploy-localmake deploy-localExplicit local Compose overlay.
deploy-productionmake deploy-productionExplicit base Compose production rollout.
 
npx nx run precis-main-assets:check
npx nx run precis-main-assets:build
npx nx run precis-main-assets:deploy-local
npx nx run precis-main-assets:deploy-production
Use cases

Where each road belongs.

Use casePreferred roadReason
Public catalog, blog, and SEO pagesFull Django/Fusion HTMLContent is available to crawlers and keeps Wagtail as the editorial source.
Enroll, save, filter, and other small interactionsHTMX fragmentOnly the changed region is returned; Alpine handles local state and feedback.
Learner dashboard and course playerAstro plus JSON APIInteractive islands can hydrate without turning every public page into a client application.
Local design and route workmake deploy-localUses the overlay and published ports without changing production configuration.
Release candidate or host rolloutmake deploy-productionUses the base stack and root secret/config contract after validation.

Do not add client-only fallback content when the API is unavailable. A missing Wagtail response is an operational error that should remain visible to the check or error state.

Source of truth: projects/precis/structa.cloud/Makefile, project.json, docker-compose.yml, and docker-compose.override.yml. Review generated output and environment values before any production rollout.
