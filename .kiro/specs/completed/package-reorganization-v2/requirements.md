# Requirements: Package Reorganization v2

## Overview
Reorganize the 4-package monorepo (django-osoul, django-rseal, nawaai/crafts-ai, django-grep)
around clear use-case boundaries with zero cross-package shims, automated boundary enforcement,
and namespace documentation at every directory level.

---

## User Stories

### 1. Foundation Boundary
As a developer, I want `django_osoul` to contain only Django + stdlib code (plus Wagtail in comp/)
so that it can be used in any Django project without pulling in automation dependencies.

**Acceptance Criteria:**
- `django_osoul` (excluding comp/) has zero wagtail/celery/AI/rseal imports
- `django_osoul.routes` provides Viewset, BaseViewset, route(), menu_path()
- `django_osoul.contrib` provides DEFAULT, camel_case_to_underscore, utility functions
- `django_osoul.rendering` provides TemplateRenderer
- `django_osoul.views.mixins` provides BaseDashboardMixin, BaseCartMixin

### 2. Automation Boundary
As a developer, I want `django_rseal` to contain only automation code (email, tasks, newsletter)
so that its purpose is clear and it doesn't duplicate foundation concerns.

**Acceptance Criteria:**
- `django_rseal.seeder` is a deprecation shim → `django_grep.seeder`
- `django_rseal.renderer` is a deprecation shim → `django_osoul.rendering`
- `django_rseal.ai` is a thin adapter → `crafts_ai.ai`
- `django_rseal` does not import from `django_grep`

### 3. AI/MCP Boundary
As a developer, I want `crafts_ai` to contain all AI core code with zero Django dependency
so that it can be used in non-Django projects.

**Acceptance Criteria:**
- `crafts_ai` has zero Django imports
- `crafts_ai.ai` provides OpenAI, Claude, Rasa integrations
- `crafts_ai.chat` provides CraftsClient, ChatBubble, RasaClient
- `crafts_ai.mcp` provides MCPServer
- `crafts_ai.seeder` provides SimpleSeeder (no ORM)

### 4. Testing Boundary
As a developer, I want `django_grep` to be the single home for all test utilities and seeder
so that test data generation is co-located with the testing framework.

**Acceptance Criteria:**
- `django_grep.seeder` provides Seeder, ModelSeeder, guessers, providers
- `django_grep.tests` provides BaseTestCase, BaseAPITestCase, ModelFactory, AssertEmailMixin
- All tests from `libs/tests/` are moved to `django_grep/tests/`
- `libs/tests/` directory is removed

### 5. Centralized Tests
As a developer, I want all package tests to run from `django-grep/tests/`
so that there is one command to run the full suite.

**Acceptance Criteria:**
- `libs/tests/test_*.py` moved to appropriate `django-grep/tests/test_*/` subdirs
- `libs/tests/` directory deleted
- `pytest` from `libs/django-grep/` runs all tests

### 6. Automation Scripts
As a developer, I want shell/Python scripts to automate boundary checks, test runs,
seeder migration, and namespace doc generation.

**Acceptance Criteria:**
- `scripts/libs/run_tests.sh` runs the full test suite
- `scripts/libs/check_boundaries.sh` verifies package boundaries (exits 0 on pass)
- `scripts/libs/move_seeder.sh` migrates seeder from rseal → grep
- `scripts/libs/generate_namespace_docs.py` writes README.md at every package dir
- `scripts/libs/scan_imports.py` reports boundary violations

### 7. Namespace Documentation
As a developer, I want a README.md at every Python package directory
describing the namespace, public API, and usage example.

**Acceptance Criteria:**
- Every `__init__.py` directory in all 4 packages has a sibling README.md
- README.md shows: namespace path, public API, usage snippet
- READMEs are auto-generated by `generate_namespace_docs.py`

### 8. Directory Tree Documentation
As a developer, I want the full target directory tree documented in the plan
so that the intended structure is unambiguous.

**Acceptance Criteria:**
- `docs/specs/package-reorganization/plan.md` contains full target dir trees for all 4 packages
- Plan includes import path change table
- Plan includes success criteria checklist

---

## Non-Functional Requirements

- No circular imports between packages
- Boundary check script exits 0 (all pass) after reorganization
- All existing tests continue to pass
- Each package README reflects actual import paths after reorganization
